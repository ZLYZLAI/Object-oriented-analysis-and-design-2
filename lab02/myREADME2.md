# Отчёт по лабораторной работе №2
## Структурные паттерны проектирования

**Тема:** Реализация паттерна «Приспособленец» на языке C++ для оптимизации игрового редактора карт

---

## 1. Цель работы

- Изучить теоретические основы структурных паттернов проектирования, в частности паттерна «Приспособленец».
- Научиться разделять состояние объекта на внутреннее (разделяемое) и внешнее (контекстное).
- Реализовать систему эффективного хранения и рендеринга большого количества графических объектов.
- Закрепить навыки работы с динамической памятью (`shared_ptr`), контейнерами STL (`map`) и библиотекой SFML.
- Провести сравнительный анализ потребления ресурсов системы при использовании паттерна и без него.

---

## 2. Описание предметной области

В рамках данной работы рассматривается разработка графического редактора «ВАУ-СТРОИТЕЛЬ 3000». Программа позволяет пользователю создавать игровые карты, размещая объекты на сетке. Предметная область характеризуется следующими факторами:

| Фактор | Описание |
|---|---|
| **Масштабность** | На карте могут одновременно находиться сотни и тысячи объектов (плитки травы, леса, стены) |
| **Тяжёлые ресурсы** | Каждый графический объект требует загрузки текстуры, которая занимает значительный объём в видеопамяти и RAM |
| **Дублирование данных** | Множество объектов на карте (например, «Ель») имеют идентичные визуальные свойства и различаются только положением |
| **Производительность** | Процесс отрисовки и загрузки карты не должен вызывать падения FPS или задержек из-за избыточного чтения с диска |

---

## 3. Решение: применение паттерна «Приспособленец»

Для оптимизации работы с ресурсами был выбран паттерн **Приспособленец**. Он позволяет поддерживать огромное количество мелких объектов за счёт выноса общих данных в отдельные разделяемые структуры.

В проекте паттерн реализован следующим образом:

- **Разделение состояния** — данные об имени типа и текстуре вынесены в класс `ObjectType` (внутреннее состояние), а координаты `x, y` оставлены в `MapObject` (внешнее состояние).
- **Кеширование ресурсов** — загрузка текстур происходит строго один раз. При попытке создать второй объект того же типа система выдаёт ссылку на уже существующий ресурс.
- **Управление временем жизни** — использование `shared_ptr` гарантирует, что тяжёлый объект типа будет существовать в памяти ровно до тех пор, пока на него ссылается хотя бы один объект на карте.

### 4.2. Роли классов

| Класс / Структура | Роль | Описание |
|---|---|---|
| `ObjectType` | Приспособленец | Хранит «тяжёлую» информацию (текстуру), общую для всех экземпляров |
| `ObjectFactory` | Фабрика | Управляет пулом объектов `ObjectType`, предотвращая дублирование ресурсов в памяти |
| `MapObject` | Контекст | Лёгковесный объект, представляющий конкретную точку на карте |
| `GuiButton` | Клиентская часть | Обеспечивает интерфейс взаимодействия пользователя с редактором |

### 4.3. Детальное описание реализации

#### Структура `ObjectType` (внутреннее состояние)

Содержит данные, которые никогда не меняются для конкретного вида объекта. Текстура загружается из папки `assets/` один раз.

```cpp
struct ObjectType {
    wstring name;
    string filename;
    sf::Texture texture;

    ObjectType(const wstring& n, const string& file) : name(n), filename(file) {
        if (!texture.loadFromFile("assets/" + file)) {
            wcerr << L"Ошибка загрузки: " << n << endl;
        }
    }
};
```

#### Класс `ObjectFactory` (пул ресурсов)

Сердце паттерна. Использует `map` для поиска уже загруженных типов по их имени.

```cpp
class ObjectFactory {
private:
    map<wstring, shared_ptr<ObjectType>> types;
public:
    shared_ptr<ObjectType> getType(const wstring& name, const string& file) {
        if (types.find(name) == types.end()) {
            types[name] = make_shared<ObjectType>(name, file);
        }
        return types[name];
    }
};
```

#### Структура `MapObject` (внешнее состояние)

Объект, фактически хранимый в `vector<MapObject>`. Весит всего несколько байт — два `int` и один указатель.

```cpp
struct MapObject {
    int x, y;
    shared_ptr<ObjectType> type;

    void draw(sf::RenderWindow& window, int gridSize) {
        sf::Sprite sprite(type->texture);
        sprite.setPosition((float)x * gridSize, (float)y * gridSize);
        float s = (float)gridSize / type->texture.getSize().x;
        sprite.setScale(s, s);
        window.draw(sprite);
    }
};
```

## 5. Вывод и сравнительный анализ

### 5.1. Сравнение подходов

| Характеристика | Без паттерна (монолит) | С паттерном Приспособленец |
|---|---|---|
| **Расход RAM** | Растёт пропорционально количеству объектов | Растёт незначительно (только координаты) |
| **Использование VRAM** | Каждая плитка травы дублирует текстуру в видеопамяти | Одна текстура на все объекты одного типа |
| **Время загрузки** | Зависит от количества объектов (постоянное чтение HDD) | Зависит только от количества типов объектов |
| **Масштабируемость** | Ограничена (при 1000+ объектах возможен вылет) | Практически не ограничена объёмом RAM |

## 6. Заключение

В ходе работы был реализован графический редактор с применением паттерна «Приспособленец». Использование данной архитектуры позволило:

- **Изолировать ресурсы от логики их размещения**, что соответствует принципу единственной ответственности.
- **Оптимизировать производительность** за счёт исключения повторных операций ввода-вывода при создании объектов.
- **Обеспечить масштабируемость** приложения, позволяя создавать детализированные карты без критического потребления ресурсов ПК.

> **Итог:** паттерн "Приспособленец" доказал свою эффективность для систем с большим количеством повторяющихся тяжёлых объектов.
